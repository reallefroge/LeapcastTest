# Leapcast Studio AI

A lightweight Windows streaming studio built to look great on **low upload bandwidth**, tuned for
low-motion games like **Wizard101** plus a webcam.

## What it does

| | |
|---|---|
| **Capture** | Screen via GPU desktop duplication (works with fullscreen DirectX games, near-zero CPU) or GDI; a single game window; webcam (DirectShow); image and text overlays; microphone and desktop/game audio (WASAPI). |
| **Multistream (Aitum-style)** | Stream to Twitch, YouTube, TikTok, Kick or any RTMP(S) server at once. Each destination is its own row with a status light, live bitrate, and its own ▶/■: start, stop or reconnect one without touching the others. All destinations share one encode per canvas (no extra GPU/CPU); a destination can optionally get its own encode at a different bitrate. |
| **Vertical canvas** | A second 9:16 canvas for TikTok / Shorts / Reels with its own layout: camera on top, game full-width below over a blurred copy of itself, automatically. Drag things on the vertical preview to change it. |
| **Edit on the preview** | Drag sources to move them, drag any corner or edge to resize (the picture keeps its shape; the opposite side stays put), **Shift**+drag to stretch it freely, **Ctrl+Shift**+drag an edge to crop it (right-click → Reset crop / Reset shape to undo), lock a source (🔒 in the list, or right-click → Lock) so it can't be moved or resized by accident, snap to edges and centre lines (hold Shift to place freely), arrow keys to nudge, right-click for corner snaps, or right-click a webcam → Flip horizontally. Moves apply live, with no restart and no blink, even while streaming. |
| **Auto-config** | One click: optionally scans your upload speed (in kbps, about 10 s: Twitch's invisible test mode when you have a Twitch key, otherwise an upload test over the internet) and fits the bitrate so every destination gets its full bitrate within 75% of it; measures your game window, picks the GPU encoder and a webcam mode that matches the stream's frame rate, then stress-tests your real scene (capture + every scene + encode, nothing goes live) and steps down until it keeps up. |
| **Any game size fills 16:9** | Full-screen sources default to *crop to fill*: an 800×500 (16:10) window fills the whole 16:9 stream with the edges trimmed, never stretched and with no black bars. *Fit* and *Stretch* are there if you prefer. Auto quality never upscales a small window (that only costs data). |
| **Game window capture that survives** | Each game window is captured by its own small process at a steady frame rate. If the game recreates its window (loading screens, resolution changes) the capture re-attaches by itself while the stream keeps running. |
| **Browser source** | Any URL (chat, alerts, widgets) rendered off-screen with a transparent background by Microsoft Edge WebView2 (built into Windows 10/11). Frames are only produced when the page changes, so an idle chat costs almost nothing. Custom CSS is injected into the page. |
| **Camera sync (clap test)** | Clap a few times in view: Leapcast measures how far the camera trails your voice and corrects it. |
| **One encode, many outputs** | The stream, recordings and instant replay all come from the **same** encode. Recording while live costs no extra GPU/CPU. |
| **Smart VBR** | Quality-targeted encoding with a hard bitrate cap. Static screens (menus, waiting for your turn, dialogue) use a fraction of the cap; battles can use all of it. In testing on mostly-static game-like content at a 3,500 kbps cap: **~965 kbps vs 3,607 kbps** for constant bitrate. |
| **Auto quality** | Picks resolution/FPS/bitrate from your measured upload (Twitch test mode, invisible to viewers), the strictest platform limit and your hardware. Like Aitum Multistream, every destination sharing an encode gets its full bitrate (nothing is divided), the vertical canvas has its own bitrate, and any output can have its own encode at its own bitrate. If they add up to more than is safe for your upload, Leapcast warns you. |
| **Best encoder automatically** | Test-encodes NVENC, Quick Sync, AMF and x264 at startup with their high-efficiency settings (look-ahead, adaptive quantization, B-frames), falls back to safe settings on older GPUs, then picks the best one for your PC. |
| **Webcam denoise** | Light temporal denoise after downscaling. Sensor grain in a dim room is one of the biggest bitrate wasters on a gaming stream. |
| **Audio mixer** | A dB fader (−60 to +20 dB) and a mute button for every audio source, plus a **Stream output** master fader. Changes apply live; double-click a fader to reset it to 0 dB. Meters show the level after the fader. |
| **Voice clips** | Turn on **🎙 Voice clips** (next to Record) and say **"Clip"** while live or recording; recent footage is always kept while live, so there is no replay buffer to start. Mic audio is low-pass filtered before it is downsampled for the recognizer. Leapcast saves the 15–60 seconds (your setting, default 50) that end just before you started saying the word, so the word itself isn't in the clip. Clips go to `Videos\Leapcast\clips`, named by date and time (e.g. `2026-11-04 15-57-32.mp4`). Sensitivity: Normal, High (default) or Maximum. Recognition runs offline with Vosk (Kaldi) on the stream's mic: everything said is transcribed into ordinary words and only a transcribed "clip" counts, so other talking can't set it off. The clip is cut from the already-encoded stream. `logs\voice.log` records what was heard; `logs\voice-audio` keeps a few seconds of audio around each hit and near miss (last 40) for tuning. |
| **Sources and folders** | The top of the sources list is drawn in front, like OBS. Each source has an eye (lit = shown) and a lock. Folders group sources: their eye hides everything inside, their lock locks it, and while unlocked, dragging the folder on the preview moves its sources together. Drag rows to reorder or drop them onto a folder. |
| **Status bar** | Bottom right: stream health, bitrate (with upload congestion, live only), encoder load (live only) (overloaded / busy / OK, details on hover), FPS, live uptime and recording time. |
| **Performance log** | While anything is running, `logs\performance.log` gets a line every 10 seconds: what is being composited and encoded, the encoder's fps and speed, CPU and memory for Leapcast and each thing it runs (encoder, capture, destinations, browser sources), and how far behind each capture reader is. It is what to look at — or send — when the app is using more of the PC than it should. |
| **VOD editor** | Tools → "Edit a recording into a video…": an hour or more of stream becomes an edited video (15 minutes by default). It finds the moments (your reactions and words, clips you saved, Wizard101 fights and deaths, chat spikes, action on screen), drops dead air and loading screens, and edits them like a highlights editor: a **hook** (two of your biggest moments in flashes, then the run-up to the best one, with your line on screen), **your channel's intro** (the same every video so it sticks: your channel name in gold Cinzel lettering, your logo if you drop one in, an intro clip and intro music from your Wizard101 kit), Wizard101-styled text on every video (gold, deep night blue and a fantasy serif, Among Us included), chapters named after your best line, jump cuts, punch-ins and face-cam zooms on reactions, slow motion with a tape stop on deaths, word-by-word captions (Whisper, from your mic's own track, so it's only your voice), a colour grade, music from your **Wizard101 kit** (Videos\Leapcast\Wizard101 kit: it fills itself, each Wizard101 recording you edit adds stretches of the game's own music where nobody talks, and the first sets the intro clip and its music; add your own tracks, logo or intro clip any time) kept low under your voice, or no music, sound effects, loudness at YouTube's -14 LUFS, a 20-second **end screen** laid out for YouTube's end-screen elements (previous video, watch next, subscribe: the steps to add them in YouTube Studio are in the description file), a thumbnail with your face, and a description with chapters (chapters are optional: untick "Chapters" for no chapter cards and none in the description). **Among Us** recordings are edited around the game: the best stretches of each round (moving around, tasks, kills) and each meeting's best moments (accusations, everyone talking, the vote and the ejection), with other players' voices counted, and never a frame of the lobby ("WAITING FOR HOST" / room settings). **VAR checks** (Among Us): when you say where you were in a meeting ("I was in electrical…", on your mic only, never the speakers), the meeting dims, a VAR CHECK banner shows your words, and a fast replay of your round slides in over it. **Transitions**: plain cuts unless you ask. Pick a style for the whole video (whip pan, fade through black, flash to white, blur, zoom punch, glitch, timelapse that fast-forwards the gameplay in between with the speed shown, or varied: the editor's pick per cut, never the same twice running) and, separately, their sound (none, whoosh, soft whoosh, pop, impact, riser, matching or varied). Every cut lists the editor's suggestion and why, and you can set any single cut. **Your camera in the edit** (recordings made in Leapcast know where it is): shape it (rounded, oval or circle, with a thin gold ring; drawn big enough to cover the camera's old square, so no corner shows), and blur or remove the background behind you (a person segmentation model, OpenCV Zoo's PP-HumanSeg (Apache 2.0), cuts you out frame by frame; where it's removed, the old square is filled from the game around it); in the panel or in your own words ("make my camera oval", "remove my background"). **No flashing, ever**: flashing light can be a problem for viewers, so no flash transitions and no flashes anywhere (a request for one gets a fade through black). **The editor's suggestions** (in the review/revise panel, refreshed as you change things): where you explained where you were in a meeting (a VAR check replay of that round, one by one), clips you saved and deaths or big reactions that didn't make the cut, cuts where a transition would mark a change, long stretches where nothing is said, and the hook / end screen / slow motion / captions when they're off. ▶ watches the spot, Apply adds it as a suggestion line (so you see what it changed), ✕ dismisses it for good; with a short guide to asking for fixes in your own words. **Checked before it's saved**: every clip is watched back (one that's mostly frozen, black or silent is swapped for the next best moment), every part's loudness is measured from the clip itself and brought to one level, and the finished video is listened to again part by part (anything still off is corrected and checked again); a revision that wouldn't change the video says so instead of rendering the same file. "I hate the clips" picks all-new moments. **Fully automatic or review first**: review mode plans the edit and shows every cut and moment before anything is rendered, with a **player** in the window: ▶ next to any moment or cut plays it, “Quick preview of the edit” makes a small fast draft of the whole edit to watch (only changed parts are remade on the next preview), and “Note at this time” drops the time you're at into your feedback. After rendering, the video plays there too. **Revise** in your own words, one suggestion per line (Enter applies it, shows what changed under it, and starts the next line; a line with a time from “Note at this time” changes just that spot: “at 4:12: this part is boring” removes it, “at 3:20: use a fade here” sets that one cut) ("remove transitions", "I don't want the transition sounds", "the volume jumps between clips", "too chaotic", "glitch transitions", "a fade at 3:20"): typos and different wordings are understood, and anything it can't change is just noted. Even loudness between parts on request. Any earlier version can be the starting point of a revision ("Start from"). **Learns your taste**: every video you make or revise is remembered per game, and a choice you make in two or more edits becomes where new edits start ("Forget what it learned" starts fresh). Captions are written while the clips render, and clips are encoded on your graphics card when you're not live. Saved to Videos\Leapcast\VODEdits. Recordings made in Leapcast carry a session log (your mic transcript, clips, deaths, chat) that makes the edit sharper. |
| **Dockable panels** | Every panel (scenes, sources, controls, audio mixer, multistream, stats, activity, stream info) can be dragged to another spot, docked as a tab, or popped out into its own window, like OBS docks. The layout is saved; Docks → Reset layout puts everything back. |
| **Audio mixer** | Vertical channel strips: segmented LED meters (green / amber above -20 dBFS / red above -9 dBFS) with a 1.5 s peak hold, a dB scale, a lit fader and a gain readout. |
| **Hide from capture** | Settings → Advanced → "Hide Leapcast from display capture": the Leapcast window, its dialogs and popped-out panels are left out of display captures (viewers see what's behind them). |
| **Stream info** | A panel with Twitch's "Edit Stream Info" and YouTube Studio's live page (sign in once inside it) to change title, category and tags without leaving Leapcast. |
| **YouTube broadcast picker** | Going live on YouTube asks which broadcast: your live and scheduled ones (soonest first). The one you pick gets a stream key no other broadcast uses (one key shared by several scheduled broadcasts can land the video on the wrong one), and is switched to live once YouTube receives video. **Quick new broadcasts** (on/off in Settings → Connection): title, description and privacy right in the picker, made and gone live on in one click; with nothing scheduled, Enter does it. Needs a free Google "Desktop app" client of your own, set up once right in the picker (steps and a button to the Google Cloud console there). |
| **Multi-client** | Several clients of one game at once (e.g. multiple Wizard101 accounts): the multi-client button in Sources gives every open client its own window capture and tiles them side by side (2 → side by side, 3-4 → 2×2, 5-6 → 3×2), each keeping its shape, under your camera and overlays. Clients share one title, so they're told apart by the order they were opened ("Client 1, 2…" in a window source's properties). Press it again after opening or closing a client. |
| **Balance my audio** | A 16-second test in the mixer (you talk, then the game plays) sets the microphone and game faders so your voice peaks around -6 dB with the game about 12 dB under it, and the stream output to 0 dB. |
| **The stream comes before the preview** | If the PC falls behind real time, the preview is slowed first (and comes back after a calm minute): viewers never pay for the preview. |
| **Crop outline** | While a cropped source is selected (and while you crop with Ctrl+Shift+drag), the part that's cut away is tinted and outlined in green dots. |
| **Settings while live** | Anything that would restart the encoder is greyed out with "Unable to Change while Live"; everything else applies without touching the stream. |
| **Revise an edit** | After an edit (or "Revise an earlier edit…"), say what to change in your own words: "music quieter by 50%", "rename part 2 to Khrysalis boss fight", "remove the part at 3:20", "add the moment at 1:12:30 of the stream", "more funny moments", "too many zooms", "faster pace", "make it 12 minutes". It shows what it understood; edit the chapter cards' text and the title directly, untick moments, set music volume, pace, zooms, slow motion, face cuts and cold open. Re-rendering doesn't watch the recording again and reuses every part that didn't change; each revision is a new version next to the last. |
| **Chat & alerts** | A **Chat** panel with Twitch and YouTube chat together (name colours, badges, emotes); no keys or sign-in, just the channel (Settings → Chat & alerts; YouTube is found automatically when you go live). **Pop out** the chat into a slim window you can pin on top of the game, with a see-through background. **Alerts** for subs, resubs, gifted subs, bits and raids (Twitch) and Super Chats, Super Stickers and memberships (YouTube), straight from chat; add an optional Streamlabs socket token for follows, YouTube subscribers and donations (matched so nothing pops twice). Chat panel → ＋ adds the **alerts overlay** (or a chat overlay) to your scene; the 🔔 button fires test alerts; a chime plays with each alert. |
| **Stream safety** | Settings → Safety (also Settings → Stream safety… and the 🛡 badge). **Safety delay** (on/off, 2–5 s, 2 s by default): desktop audio (the game, Discord) waits inside Leapcast so a word can be heard before it goes out; the stream, recordings and clips run that far behind, in sync, while your preview stays live. **Slur filter** (needs the delay): two recognizers listen on this PC. A quick keyword listener holds back anything that might be a filtered word the moment it's said; the full recognizer then keeps it muted (a slur, or the n-word / f-word said casually or cut short) or lets it go out untouched (an ordinary word like "bigger" or "trigger"). Racial, ethnic and anti-LGBTQ slurs are built in, optionally the r-word, plus your own words. **Game codes** (Among Us): letters read out ("C, E, U, W, Y, B", "see, e, you, double-you…") are cut after someone says "code" or "lobby", and otherwise any 4+ letters in a row read at a spelling pace; "oh I see you" said normally is left alone. Optionally your microphone too. **Loud audio protection**: a blown-out Discord mic, a screamer or a soundboard blast is turned down to a comfortable level within 10 ms and eased back after; ordinary loud game moments are left alone; works with or without the delay. |
| **Camera auto light** | On by default per webcam (Properties → Auto light): once a second it samples the picture (centre-weighted) and gently adjusts gamma, contrast and colour, so a dark room is lifted and a blown-out one calmed, without pushing lamps or windows into white. A well-lit picture is left exactly as the camera made it. Costs almost nothing (one small filter, changed only when you'd see the difference). |
| **Clip captions** | What you say during a clip is burned into it as short TikTok-style captions (white, outlined, under the game on 9:16 clips). Your mic is transcribed on this PC by Whisper (whisper.cpp, base.en: much more precise; the 148 MB model downloads once on first use) from the last 4 minutes of your mic, kept in memory only; until the model is there, the live recognizer (Vosk, the same one as voice clips) is used. Caption lines never overlap and repeated words are merged. Your desktop audio is transcribed too, so words that leak from the speakers into the mic (the game, Discord) are left out, and a "clip" they say doesn't trigger a clip. Settings → Recording → "Captions on clips". |
| **9:16 clips** | Clips are saved as 9:16 for TikTok / Shorts (only the 9:16 file is kept): a small camera near the top with rounded corners (a wide webcam trimmed to 4:3), the game big below it (the middle of the picture filling the width), a blurred game behind, optional handle text. Rendered at low priority with the GPU encoder. Turn it off in Settings for 16:9 clips. |
| **Wizard101 death clips** | When the red health globe empties (HP 0: a gray globe with a yellow "0"), Leapcast saves the fight that led to it: from just before your HP started changing (up to 5 minutes) to just after the death ("… death.mp4"). |
| **!clip from chat** | Twitch chat is read anonymously (no login); when you or a mod (VIPs / everyone optional) types `!clip`, a clip is saved ending a few seconds before the message (viewers watch with a delay). The channel is taken from your Twitch chat source. |
| **Stream recap** | When a stream ends, its clips (and 9:16 copies) are gathered in a "Recap" folder with a highlight reel (title card, the last 20 s of each clip, an outro card with your socials) and a thumbnail from each clip. |
| **Light mode** | Hidden sources aren't captured (showing one takes about a second; destinations stay connected). Every scene's shown sources keep running, so switching scenes is always a seamless fade. Settings → Advanced → "Keep hidden sources running" turns it off. |
| **Timer** | A **Timer** dock (Docks → Timer) counts down, counts up, or shows the clock, and **Add to scene** puts it on the stream as a source. Type the length as `25m`, `1:30:00`, `1h30` or `600`; Start/Pause, Reset, and ±1/5/10 minutes while it runs. Give it a title ("SUBATHON", "BREAK") and pick a shape: *stacked* (title over the clock), *inline* (title beside it) or *plain* (digits only, no plate). The card is sized for the longest reading it can reach, so nothing shifts as the digits change, and it is drawn at its own size — no scaling, no blur. The reading is re-read every frame, so it ticks without restarting the encoder. Needs a fixed-width font (Consolas on Windows). |
| **Record in 9:16 only** | Settings → 9:16 clips → "Record in 9:16 only (for TikTok)". Record then saves the vertical picture instead of the widescreen one, ready to upload as it stands (the file is named `… 9x16.mp4`). With a vertical canvas set up it records your own 9:16 layout; without one it records the automatic clip layout (small camera on top, the game big below). The stream, clips and instant replay are unchanged, and no 16:9 encode is run just to record. |
| **A preview that costs nothing** | The preview's pictures are made only as fast as someone looks: full speed while Leapcast is in front, a third while you're in another app (the game), none while it's minimized or the preview is off (a couple a second if death clips need to watch). The rate changes live, without a restart, and the stream never needs the preview. Settings → Advanced keeps it at full speed in the background (for a second monitor). |
| **Less work per frame** | One speech recognizer per audio source: the safety filter's also provides the desktop transcript, and silence isn't transcribed. Browser pages reach FFmpeg already in the overlay's format (YUV + alpha, 2.5 bytes a pixel), converted only when the page changes. With auto light, webcam denoise runs only while the room is dark, and a neutral colour correction is switched off. |
| **Mic cleanup** | High-pass plus adaptive FFT noise reduction (fans, hum, hiss). |
| **Adapts to any PC, live** | A governor watches three signs every second: whether the encode keeps up with real time, whether frames are queuing up in front of the compositor (this happens before stutter is visible), and whether each destination's upload is keeping up. If the PC falls behind it steps down a ladder, cheapest-to-notice first: lighter encoder settings → 30 FPS → only the on-air scene is captured → a smaller picture. Heavy lag is handled within seconds, mild lag within ~10 s. It only steps back up after two calm minutes while nothing is live or recording, and never back into a setting that failed recently, so it doesn't flap. A slow upload gets less bitrate instead of a lower picture quality, and a pipeline that freezes outright is restarted by a watchdog. Low-end PCs (4 threads or fewer, under 6 GB RAM, or CPU-only encoding on 8 threads or fewer) start at 30 FPS with light settings. Toggle it in Settings → *Adapt to my PC automatically*. |
| **Never drops the stream** | Switching scenes, showing or hiding a source, changing volume and staging scenes in studio mode all happen inside the running encoder. Nothing restarts, so viewers see no blink. Bigger edits (cropping, resizing, adding a source, the adaptive governor's lighter settings) rebuild the picture pipeline, but every destination stays connected: the connection is handed over to the new encoder and viewers see a pause of about a second instead of a disconnect. Only a change of stream resolution reconnects. |

Each type shows how many you have. |

Only that source is touched and the stream keeps going (it holds its last picture meanwhile). A screen, image or text is read again with a quick rebuild, and Leapcast asks first while you're live. **Clear cache** (web pages and images) throws away the saved copies and loads them fresh; you stay signed in. On a folder, both apply to everything in it. |

Stream keys are encrypted with a password you choose (AES-GCM) or left out; they're never written in plain text. **Import** on a fresh install recreates the profile exactly. |
| **Hotkeys everywhere** | Settings → Hotkeys: go live/end, record, save replay, preview, studio mode, transition, switch to each scene, and show/hide each source. They work while the game has focus, and a key combination used twice is caught when you save. |

Moving, resizing, showing, hiding and switching never rebuild anything. Falls back to the classic compositor by itself for screen captures, the 9:16 canvas, 9:16 clips and studio mode. |
| **Reliability** | Leapcast never ends a stream or recording by itself: only you do. If the encoder dies (a driver hiccup, a capture that breaks), it's restarted right away and again with back-off for as long as it takes. The destinations wait connected-or-reconnecting and the recording carries on in the new run. If it broke right after the adaptive governor changed settings, the settings that were working come back. Every stop is written to logs\stream-health.log with its reason, and the failed FFmpeg run is kept as logs\ffmpeg-crash.log. Each destination that was live reconnects on its own with back-off, forever; a slow destination can't stall the encoder, the recording or the other destinations, and if its upload keeps falling behind the bitrate drops 25% automatically. All inputs are wall-clock synced so game, cam, mic and desktop audio stay aligned. |
| **Frame rate per source** | Every capture source has its own **Frames a second** in its properties (default: same as the canvas, never faster). The game you are playing needs 60; a second client in the corner, a webcam, an overlay or anything that barely moves does not, and capturing it at 30 on a 60 FPS stream halves that reader's work — the canvas just repeats its frames, and nobody can tell. There is also **Capture at full resolution** for a window you zoom or crop into: normally a window is shrunk to the size the canvas shows it at while still on the graphics card, which is cheaper and looks the same. |
| **Game Capture** | A source type for games, using Windows' own graphics capture: it works in windowed, borderless **and** fullscreen, leaves the game's frame rate alone, and is cropped, scaled and converted on the graphics card so only a finished picture is copied back. It fills the canvas and hides the mouse pointer by default, and has its own frame rate like any other source. (It captures the game's window through the operating system; it does not inject anything into the game.) |
| **Canvas shape** | Settings → Canvas & scenes → Canvas: **widescreen 16:9 only**, **vertical 9:16 only**, or **both, side by side**. 9:16 only *replaces* the widescreen picture everywhere — the preview, the stream, recordings and clips are all 9:16, destinations all get the vertical feed, and no widescreen canvas is built at all, so it costs less than running both. The program preview becomes the 9:16 one and dragging in it moves the 9:16 positions. Both keeps the two beside each other, each with its own destinations and bitrate. |
| **Scene transitions** | Every scene stays live inside one encoder, so switching (e.g. Wizard101 → "BRB") is a smooth crossfade or a clean cut: no restart, no black frame, and the recording/replay keeps running. Audio levels crossfade too. A camera used in several scenes is opened only once. This holds in light mode too: only *hidden* sources are unloaded there. The switch itself costs the same whether you keep two scenes or twenty: two selectors pick the outgoing and incoming pictures and one crossfade blends them, instead of a mask and a blend for every scene you own (measured: that used to cost about 8% of a processor core per extra scene at 1080p30, so eight scenes now composite for 39% less). |
| **Live stats** | Real upload (measured from the encoded output), average, % data saved vs constant bitrate, frame rate, connection health, and *why* each setting was chosen. |

### Recommended setup for Wizard101 + camera
Click **Auto-config** (top right) with Wizard101 open: it does most of the steps below for you.

1. Multistream panel → **+ Add output** → Twitch (paste the key), again for YouTube, and TikTok (server URL + key from TikTok LIVE Producer; it asks for a fresh key each time you go live).
2. Settings → Connection → **Test my connection**. Quality: **Low-motion game**, Profile **Auto**, Bitrate mode **Smart VBR**.
3. Scene: **Display Capture** (GPU) of the monitor with Wizard101 + **Video Capture Device** (your cam, Smart denoise on) + **Desktop audio** + **Microphone** (Noise cleanup on). Drag the camera where you want it on each canvas.
4. **Go live** starts every enabled output; each row can also be started and stopped on its own.

TikTok LIVE from a PC needs LIVE access on your account (TikTok currently asks for 1,000+ followers and age 18+) and a key from LIVE Producer, which usually changes every stream.

At 30 FPS, Wizard101 looks the same as at 60 FPS, because the game is turn-based and its camera moves slowly. 30 FPS needs roughly half the data.

## Build
Requirements: Windows 10 22H2+/11 x64, the .NET 10 SDK, and [Inno Setup 6](https://jrsoftware.org/isinfo.php) for the installer.

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\scripts\build-installer.ps1              # publish + bundle FFmpeg + build setup EXE in .\dist
.\scripts\build-installer.ps1 -SkipInstaller   # just the app folder in .\publish\win-x64
```
The script downloads a Windows x64 **GPL** FFmpeg build (BtbN/FFmpeg-Builds, preferring the 7.1 branch) into `publish\win-x64\ffmpeg\bin`.
Pass `-FfmpegZip path\to\build.zip` to use one you downloaded yourself.

For development: `dotnet run --project .\src\LeapcastStudioAI` (put `ffmpeg.exe` on PATH or set it in Settings → Advanced).

### Engine tests
The engine core (`src/LeapcastStudioAI/Core`) is platform-neutral and is exercised end-to-end against real FFmpeg (run on Linux/macOS/WSL: the device stand-ins use `mkfifo`):
```bash
dotnet run -c Release --project tests/CoreTests
```
It covers the smart tuner, encoder argument sets, multistreaming to local RTMP servers (joining mid-stream, stopping one destination while the others continue, per-destination reconnect, encoder restart), the vertical canvas, live source moves, a full preview → record → live pipeline (with paced raw-video and audio pipes standing in for devices), recording across pipeline restarts, replay export, A/V alignment, Smart VBR vs CBR bandwidth, the bandwidth-test measurement, false-alarm-free health monitoring, and auto-reconnect.

## Known limitations
- Switching scenes and moving sources are seamless. *Resizing* a source or changing capture settings while live rebuilds the pipeline, so the outputs reconnect for about a second.
- Turning the vertical canvas on or off while live also rebuilds the pipeline once.
- Every scene is composited continuously so it can be faded to at any moment; each extra scene costs some CPU.
- No browser sources and no game-hook capture (use Display Capture; it handles fullscreen Wizard101).
- AI background removal for the webcam isn't included.
- No speech recognizer hears every word: a slur that's mumbled, drowned out by game sound or not in the recognizer's vocabulary can still get through. Ordinary words are never cut.
- H.264 over RTMP(S) only, for maximum platform compatibility.
